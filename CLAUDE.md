# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

ESP32 firmware for an RFID chore station. Hardware: **E32R40T** (ESP32-WROOM-32E + ST7796 4" TFT + XPT2046 touch) plus an **RC522** RFID reader. ~8,200 lines of C++ across `ChoreStation/*.h` and one `.ino`. Family members scan RFID tags to see tasks, start/complete chores, earn points, and claim a no-reminder bonus that parents approve.

## Build & Flash

This project **migrated off PlatformIO to the Arduino IDE** for easier maintenance — the flat `ChoreStation/*.h` + `.ino` layout is the Arduino sketch structure, and there is intentionally **no `platformio.ini`**. Do not reintroduce PlatformIO layout (`src/`, `platformio.ini`, `lib_deps`). Build is the **Arduino IDE** flow (`ARDUINO_IDE_SETUP.md`):

- Board: **ESP32 Dev Module**, 240MHz, 4MB flash, Partition Scheme **Minimal SPIFFS (1.9MB APP with OTA)** (`PartitionScheme=min_spiffs`), upload **460800** (921600 = "chip stopped responding" on the owner's adapter). The firmware outgrew the default 1.25MB app slot; SPIFFS is unused (all data is on the SD card), and the scheme's two OTA slots are used for WiFi updates (`ota_update.h`).
- Libraries: **TFT_eSPI** (Bodmer 2.5.x), **MFRC522** (miguelbalboa 1.4.x), **ArduinoJson** (7.x). SD, WiFi, and **WebServer** (the parent web UI) are all in the ESP32 core — no extra library for the web server (deliberately not AsyncWebServer, to avoid new deps).
- **Critical:** copy this repo's `User_Setup.h` over the one inside the installed TFT_eSPI library folder. Pin/driver defines live there, NOT in the sketch. White screen after flash = this step was skipped. It MUST define `USE_HSPI_PORT`: otherwise TFT_eSPI 2.5.x creates `SPIClass(VSPI)` and `tft.init()` re-routes VSPI's MISO to GPIO12, so the RC522 (and SD) read garbage after boot while the display looks fine. The `.ino` `#error`s if the library copy lacks it.
- Serial Monitor at **115200** for boot logs. RC522 firmware version prints at boot (0x91/0x92 genuine, 0x88/0xB2/0x12 clones — all fine; 0x00/0xFF = wiring). The reader is re-probed every 5 s, so it recovers without a reboot.
- CLI equivalent: `arduino-cli compile --fqbn esp32:esp32:esp32:PartitionScheme=min_spiffs ChoreStation` then `arduino-cli upload -p <port> --fqbn esp32:esp32:esp32:PartitionScheme=min_spiffs,UploadSpeed=460800 ChoreStation`.
- CI: `.github/workflows/build.yml` compiles with pinned versions (esp32 core 3.3.10, TFT_eSPI 2.5.43, MFRC522 1.4.12, ArduinoJson 7.4.3) and runs the jsdom test plus the host tests `test/keyboard_layout_test.cpp` and `test/input_logic_test.cpp` (`g++ -std=c++17 -Wall -Wextra -Werror -I ChoreStation test/<name>.cpp`). Behaviour (touch, RFID, SD, WiFi) still verifies only on-device.
- Cloud sessions can't reach downloads.arduino.cc; everything needed is on GitHub releases (arduino-cli, esp32-core zip, esp32-libs zip, xtensa toolchain, esptool) and libraries clone from GitHub. Pass `runtime.tools.{esp-x32,esp32-libs,esptool_py}.path` as `--build-property` and stub `ctags` (the sketch forward-declares everything).

## Architecture

Header-only modules. `ChoreStation.ino` includes every `.h` and owns all globals + UI. Each `.h` is a self-contained class (`RFIDManager`, `StorageManager`, `TaskEngine`, `Scheduler`, `BackupManager`, `TimeManager`, `DisplayPower`, `SetupWizard`, `ParentAdmin`, `AudioFeedback`, `RoutineManager`, `WebUI`). No `.cpp` files.

- **Input + sound logic** (`input_logic.h`, Arduino-free, host-tested): `TouchGate` turns touch polls into one press per finger-down (time-based debounce; `requireRelease()` after modals/boot) — `loop()` dispatches `handleTouch` only on a press, and a press on a dark screen only wakes it (`display.isVisible()`). `ToneSeq` + `cues::` define every sound. `AudioFeedback` plays cues in the background with the DAC **cosine generator** (GPIO26) stepped by a one-shot **esp_timer** (works inside modals); a new cue replaces the old; `#define AUDIO_DAC_BLOCKING 1` = old blocking square wave. `TaskEngine` plays no sounds — the UI plays exactly one cue per outcome.
- **Text on kid screens** uses `txt()`/`txtFit()` (`drawString` with an explicit TFT_eSPI font: 2 = 16 px, 4 = 26 px, 7 = 7-segment digits) — never `setTextFont`, because admin/keyboard/menus assume the GLCD font with `setTextSize`. ASCII only.
- **Firmware updates** (`ota_update.h`, pure parts in `ota_logic.h` + `test/ota_logic_test.cpp`): `.github/workflows/release.yml` builds on a `v*` tag or a manual run (`workflow_dispatch`, `version` input, tags the run's commit), stamps `version.h` (`FW_VERSION`, "dev" otherwise) and publishes `ChoreStation.bin` + `version.json` (version/size/sha256) + `ChoreStation-full.bin`. `OtaUpdater::check()` fetches `releases/latest/download/version.json` over HTTPS (core CA bundle `_binary_x509_crt_bundle_start`, redirects followed); runs every 6 h only on an idle HOME screen. Install is parent-triggered only (Admin → System Info two-tap, or web `POST /api/firmware/install` → `web.pendingOtaInstall` → `runOtaInstall()` in the loop): flush data, stream to the OTA slot with SHA-256 check, restart. `verifyRollbackLater()` returns true; `ota.healthCheck()` marks the new image valid after 60 s with the SD readable, or rolls back (bootloader rollback is enabled in core 3.3.10). Repo must be public for the download URLs.
- **Text entry:** `OnScreenKeyboard::run(title, buf, size, maxLen, autoCap)` (`keyboard.h`) is a blocking modal (RFID/web/background services pause; 2-min idle cancel). Slide-to-select, types on lift. Layout is pure data in `keyboard_layout.h` and unit-tested (`test/keyboard_layout_test.cpp`) — keep it Arduino-free. Used by the setup wizard (names), admin (custom task names, tap-a-name rename in Family Settings), the child "I found a job" confirm step, and `WifiSetup::run()` (`wifi_setup.h`: scan → pick → password → connect; saves to wifi.json only after a successful connect, otherwise restores the old network). Prefix module-local color constants (e.g. `KB_`, `WS_`) — `W_OK` etc. collide with system macros and `C_*` with the .ino's `#define`s.
- **Tags & recovery:** an unknown scan shows its UID and is remembered (`lastUnknownUid`) for the web Family tab. `Screen::PAIR_TAGS` re-assigns tags to existing members (keeps names/points); reached from recovery or Admin → Family Settings (`admin.wantsPairTags`). Recovery is the blocking `runRecovery()` (BOOT pressed during the "Starting..." splash — never at power-on, GPIO0 low at reset = download mode) built on `ButtonMenu` (`button_menu.h`): every option must work from the BOOT button alone (press = next, hold 1 s = select) because touch may be what's broken. Options: re-pair tags, WiFi setup, calibrate touch, start setup over (moves family.json → family.json.old, deletes the .bak, restarts into the wizard), exit. No SD card → `Screen::NO_SD`, which retries the mount and restarts. Touch calibration is stored in `/config/touch.json` and runs on first boot, from recovery, or when the stored values fail `touchCalPlausible()`. It's only saved after two test taps land in on-screen boxes — a bad calibration makes taps silently vanish (TFT_eSPI `getTouch()` drops points mapped off-screen). Taps are logged as `[TOUCH] x,y` on serial.

- **Web UI** (`web_server.h`) runs an ESP32-core `WebServer` on port 80, reachable once WiFi is up (the home screen prints the URL). It serves a one-page editor (HTML/JS in PROGMEM) plus a JSON API that reads/writes the SAME SD files the firmware uses — `GET/POST /api/routines` ↔ `/config/routines.json`, `GET/POST /api/tasks` ↔ `/tasks/recurring.json`, `GET/POST /api/family` (names, goals, tag UIDs; edit or append, never delete — ids are array positions), `GET /api/lastscan`. Saves are validated by `StorageManager::writeRawJson` (parse-check + required top-level array, previous version kept as `.bak`, then overwrite) and raise `web.pendingTaskReload` / `web.pendingRoutineReload`; the main loop consumes those and calls `scheduler.begin()` / `routines.begin()` so edits apply without a reboot. The page keeps existing item ids on save (instances and routine progress are matched by id). `Scheduler::begin()` (boot + every template reload) runs `_syncActiveWithTemplates()`: AVAILABLE recurring instances whose template is gone are dropped, a shared (255) copy of a template that is now Per child (254) is dropped so `generateRecurringTasks()` makes each child's copy, and the rest are refreshed from their template (started/pending/finished and one-off tasks untouched). Admin edits of a recurring chore write the chosen assignment (Per child / First taker / one person) to the template; the edit screen loads it from the template, not from today's copy. The Chores tab has "Replace all chores with the examples" (`EXAMPLE_CHORES` in the page, kept identical to `SDCard_Contents/tasks/recurring.json` by the jsdom test). Optional HTTP Basic auth via `webPin` in wifi.json (user `parent`). The page's field↔JSON contract is regression-tested with jsdom (`test/web_ui_contract.test.js`, 84 checks), asserting emitted keys match the storage loaders.
- **Dashboard order** (`buildDashRows`) puts what needs the viewer's action first. Child: own IN_PROGRESS → routines in window → AVAILABLE → routines later today → PENDING_REVIEW → routines done. Parent: PENDING_REVIEW → IN_PROGRESS → AVAILABLE. Action cards (child's running task, parent's pending approval) are tinted/outlined with a next-step hint.
- **Locking:** every dashboard has a **Bye**/padlock button (bottom-left, `x < 100 && y >= 436`, checked before page navigation) that calls `goHome()`; bottom-right is **+ Job** (`JOB_BTN_X`). Idle auto-lock in `loop()` (runs even while the backlight is off, as do timeouts and message expiry): DASHBOARD/MILESTONES/DONE_PROMPT/NEWS after `IDLE_TIMEOUT_MS` (60 s); ROUTINE after `ROUTINE_IDLE_MS` (3 min — steps are done away from the screen); PARENT_ADMIN/SELF_INIT/QUICK_ADD/PAIR_TAGS after `SETUP_IDLE_MS` (90 s) — screens that change data must never stay open indefinitely (a child could approve their own tasks or pair their tag to a parent).
- **Start/finish is by tap, not scan, and the same for everyone** (no role-based rules beyond parents approving). The scan that opens a dashboard identifies the person; `canStartTask` (own or "Anyone") decides the button. **Timed** chores (`isTimed`: `minTime` or `timeout` > 0) show **START** → back to the scan screen (`goHome`) → later **I'M DONE** once the minimum has passed; the duration is logged (`CompletionLog.durationSec`, `secs` in the day log) and shown on the approval screen. **Untimed** chores are one tap: no-reminder toggle + **DONE!** (`doneNowFor` = start + finish). A running chore has **Stop - put it back** (`TaskEngine::putBack`; `claimedFromAnyone` returns a claimed "Anyone" chore to everyone). Task-screen buttons ignore taps for `TAP_GUARD_MS` after it opens so the opening tap/double-tap can't press them. A scan by someone with an IN_PROGRESS chore opens `Screen::DONE_PROMPT` for their longest-running one (`runningTaskFor`): toggle, YES, DONE! (`finishTaskFor`) or Not yet (dashboard). Dashboard paging: **< Back / More >** buttons and "Page 1 of 3" right under the cards (`PAGER_Y`; list geometry `LIST_Y`/`ROW_H` shared by draw and touch).
- **Card buttons** (`cardChip`, right edge `CHIP_X..304`): green check = one-tap DONE (no bonus claim), START = timed start, check = finish a running chore past its minimum, amber OK = parent approve (no claim, untimed only). Ignored for `CHIP_GUARD_MS` whenever the drawn list's signature changes (`lastListSig`). The rest of the card opens the task screen.
- **Progress + news:** child header = name + `totalPoints`, badge row (`nextBadge`, bar; tap → badges), today segments (done / pending outlined) + trajectory + streak ("N days to +B"). Points earned at the station show `showCelebration` (overlay, bar animated from `loop()`); a new badge `showBadgePopup` (swallows the tap). `AwayNews news[]` (RAM) collects approvals (`parentApprove`), redos (`parentRedo`, two-tap confirm), time-outs (put back on the list) and streak bonuses (`scheduler.onStreakBonus`) and is shown as `Screen::NEWS` on the next scan (scan → NEWS → DONE_PROMPT → dashboard). Message overlays: a tap outside the box also acts (`msgBoxY0/Y1`).
- **Kid-added jobs** ("I Found a Job", **+ Job**): category (3x2 grid) → preset or typed name → size → confirm: **I DID IT!** (add + submit for review) or **Do it later**. The +2 initiative bonus is an opt-in toggle (default off): on = `SELF_INIT`, off = `ADHOC` created by the child; both `requiresApproval`. One-off ids come from `newAdhocTaskId()` (30000–49999, unique among active tasks) so they can't shadow a template id.
- **Assignment labels** (station + web): 254 = **Per child** (own copy each), 255 = **First taker** for chores (one copy, claimed on start) and **Everyone** for routines. Code and comments still say "Anyone" for 255.
- **Task ids:** a recurring instance shares its template's id — that's how the scheduler avoids duplicates. Templates with `assigned` 254 expand to one instance per child (same id, different assignee); 255 = "Anyone" (visible to every child, claimed on start). New on-device ids come from `ParentAdmin::_newTaskId` (unique across active + templates, < 60000; 60000+ is reserved for routine log ids).

- **Routines** (`routine_manager.h`) are ordered checklists done under ONE scan (bedtime, get-ready-for-school). Scan → dashboard → tap the routine card → check off each step on-screen → flat bundle of points on full completion. No per-step RFID scan. Templates in `/config/routines.json`; per-day completion is a `doneMask` (bit per member) and checked steps a `stepMask[member]` (so leaving halfway keeps the checks; ticking the last step auto-finishes after `ROUT_FINISH_PAUSE_MS`, member captured), both persisted to `/stats/routines.json` and cleared at the day rollover by `Scheduler::performDailyReset`. Surfaced as dashboard cards for children (highlighted gold during their `[startHour,endHour]` window, which may wrap midnight). Offline (no NTP), only daily (`recurDays==127`) routines surface. Dashboard rows (routines + tasks) are built by one shared `buildDashRows()` used by both draw and touch so taps always match drawn cards.

- **`pins.h` is the single source of truth for GPIO.** Two SPI buses: HSPI = LCD + touch (12/13/14); VSPI = SD card + RC522 (18/19/23), sharing the bus with separate CS pins (SD=5, RFID=21). Never touch GPIO 6-11 (flash).
- **`data_model.h` holds every struct/enum**, kept flat for ESP32 SRAM. `PointTable` encodes the whole point economy (base points by size, own-mess reduction, initiative/no-reminder/streak bonuses). `computeTrajectory()` derives ahead/on-track/behind from time-of-day, never stored.
- **Main loop (`loop()` in the .ino)** is a non-blocking pump: poll RFID → poll touch → `display.update()` power state → per-task timeout checks → message-overlay expiry → auto-return/idle timers → background services (`backups.update`, `timeMan.update`, `scheduler.update`). Ends with `delay(10)`. No blocking waits in the loop itself; the only deliberate blocking is user-driven modals (keyboard, WiFi setup, touch calibration).
- **Screen dispatch** is a `Screen` enum + `switch` in `handleTouch()`; each screen has a `draw*` and `touch*` function. Redraws are explicit calls, not a render loop.

## Invariants (violating these breaks the UX contract — see the .ino header)

- **Scan = Dashboard, always.** Any tag scan from any screen jumps to that person's dashboard (with the done prompt on top if they have a chore running). No conditional interpretation, and no second scan to start or finish.
- **Task state is self-contained on the `Task` struct** (timer, `noReminderToggled`, claim, approval) — never global UI vars. Multiple tasks run in-progress at once.
- **No-reminder is opt-in by the child** (default off) and always forces parent review. Initiative (+2) subsumes no-reminder (+1); they don't stack.
- **Parents approve only from the parent dashboard.** Child task-detail never shows approval buttons. Parent override accepts the work but rejects the bonus claim, logged for audit.
- **All feedback is on-screen + DAC audio.** Onboard RGB LEDs (GPIO 16/17/22) are deliberately unused and free.

## Persistence (SD card, FAT32)

Today's counts (goal progress, streak) are **derived**, not stored: `Scheduler::doneToday` (COMPLETED without `doneEarlier` + routines done) / `pendingToday` (PENDING_REVIEW, excluding a child's self-made jobs) / `overriddenToday`. `dailyTasksCompleted`/`remindedToday` are legacy. The last reset date is in `/stats/day.json`: once time is synced, a different date runs `performDailyReset()` (catches a station that was off over midnight); offline it falls back to uptime rollover.

`StorageManager` reads/writes JSON; `BackupManager` sits in front of it with **write coalescing** — call `markTasksDirty()` / `markFamilyDirty()`, and `backups.update()` flushes on an interval or when dirty data ages out (never per-change). It writes via **shadow copies** (`_shadowCopy`) so power loss mid-write can't corrupt files, and `StorageManager::_loadJson` falls back to the `<file>.bak` shadow when the primary is missing or unparseable (`BackupManager::loadWithFallback` is an unused older variant). Daily backups + monthly archives are auto-created.

SD layout (`SDCard_Contents/` is the seed): `/config/wifi.json` (WiFi + timezone + optional `webPin`, hand-edited before first boot), `/config/family.json` (written by setup wizard — the seed ships only `family.example.json`, because a pre-copied family.json with placeholder UIDs skips the wizard and no tag ever matches), `/config/touch.json` (touch calibration), `/config/routines.json` (routine checklists, hand-edited), `/tasks/recurring.json` (task templates), plus auto-created `/logs /stats /backups /archive`. `/stats/routines.json` holds today's routine completion masks.

`routines.json` fields: `assigned` (member id, 254="Per child", 255="Everyone" incl. parents), `points` (flat bundle), `startHour`/`endHour` (surfacing window, wraps midnight if start>end), `recurDays` (same bitmask as tasks), `steps` (array of ≤10 strings, ≤39 chars each — `ROUTINE_STEP_LEN`; longer ones are cut off on load).

`recurring.json` fields: `recurDays` bitmask (bit0=Sun..bit6=Sat; 127=daily, 62=Mon-Fri), `minTime` (min seconds start→complete), `timeout` (auto-abort seconds, 0=off), `assigned` (member id, 255=unassigned), `recurHour` (appears once this hour starts; `recurMin` is stored but unused), `expires` (unfinished AVAILABLE/IN_PROGRESS copies are dropped at the daily reset instead of carrying over). Instance-only: `doneEarlier` — set by `performDailyReset` on carried-over PENDING_REVIEW copies so `_isAlreadyActive` ignores them and today's copy still generates; if a parent rejects one, `Scheduler::settleRejected` drops it when today's copy exists (else it becomes today's copy). WiFi is optional — without it everything works except NTP time sync.
