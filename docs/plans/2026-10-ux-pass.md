# UX pass plan: "get in, get out" + visible points

Source: the design review of the station (bugs B1–B8, findings 1–9, points/progress ideas, rewards sketch), plus one more bug found while planning (B9: time limits don't fire while the screen sleeps). The owner said "go ahead with all the reviewer suggested". This plan is reviewed before any code is written.

## Constraints

- Arduino IDE flat sketch, header-only modules; no new libraries. ESP32-WROOM, 320x480 portrait, resistive touch, DAC audio on GPIO26.
- Same behavior for everyone. The only role difference is that parents approve.
- Keep what's working: one scan per visit, one-tap untimed chores, START/scan/YES DONE for timed ones, Put it back, action-first ordering, routine checkmarks kept for the day, editing on the web page.
- Every phase compiles for ESP32 Dev Module with no new warnings and passes the host tests. Each phase is committed and pushed on its own, so it can be flashed and tried before the next.
- Hardware behavior (touch, sound, brightness) can only be verified on the device. Anything that changes it is called out under **Verify on device**.

## Phase 1: Input, sound, display (the "clunky" bugs)

### 1.1 Touch is acted on once per press (B2)
**Now:** the loop calls `handleTouch` on every poll that reads a touch, then `delay(180)`. A held finger repeats about every 190 ms (`ChoreStation.ino` ~365).
**Change:** add a pure, Arduino-free `TouchGate` in a new `input_logic.h`, unit-tested like `keyboard_layout.h`.
- **Down:** once it's up, a touch seen on 2 consecutive polls (debounce) is a press. It fires once.
- **Up:** the finger counts as lifted after 4 consecutive no-touch polls (about 60 ms with the loop's 10 ms delay plus SPI time). Resistive panels drop out briefly while pressed, so a single missed poll isn't a release.
- The loop passes `getTouch()` results through the gate and dispatches only on a press. The `delay(180)` goes away.
- Modal loops (keyboard, ButtonMenu, calibration) keep their own handling.
**Test:** `test/input_logic_test.cpp`:
- a held press fires once
- dropouts shorter than 4 polls don't fire again
- a release then a new press fires again
- a single-poll blip doesn't fire

### 1.2 Tapping a dark screen wakes it properly (B1)
**Now:** a touch while SLEEPING calls `display.wake()` (state WAKING). It skips `handleTouch` and doesn't refresh `lastActivityMs`, so `DisplayPower::update` sees the old idle time and sleeps again as soon as WAKING finishes. Taps during WAKING are ignored.
**Change:**
- On any press (from 1.1), set `lastActivityMs = millis()` and call `display.wake()`.
- Dispatch to `handleTouch` only if the screen was visible before the press (`ACTIVE` or `DIM`), via a new `display.isVisible()`.
- A press on a SLEEPING/WAKING screen only wakes it, which is the documented "first touch wakes" behavior.
- `wake()` from DIM is already immediate.

### 1.3 Night mode only dims an idle screen (B6)
**Now:** 21:00–07:00 sets both active and dim brightness to 30/255, which overlaps the morning and bedtime routines. `wake()` from DIM jumps to 255 regardless.
**Change:**
- Active brightness at night is `BRIGHT_NIGHT_ACTIVE = 160`; dim at night stays 30.
- `wake()` uses the last known night flag, saved by `update()`, not a hard-coded "false".

### 1.4 Sounds play once, don't freeze the screen, and mean something (B3 + points sounds)
**Now:**
- `AudioFeedback::_playTone` busy-waits with `dacWrite` + `delayMicroseconds`.
- TaskEngine and the .ino both play tones for the same event: start (`task_engine.h:82` + `.ino:542`), complete (`task_engine.h:360-364` + `.ino:567`, triple on a badge), reject (`task_engine.h:257` + `.ino:779`), plus the `scanBeep`s inside `completeTask`/`submitClaim`.
- That's 0.7–1.5 s of frozen UI per action.
**Change:**
- Remove every `audio.*` call from `task_engine.h`. Sound is a UI decision and the .ino plays exactly one cue per outcome.
- Make `AudioFeedback` non-blocking. A small note queue (≤8 notes of frequency + duration) is played by `audio.update()` from `loop()`, using the ESP32 LEDC tone generator on GPIO26 (`ledcAttach`/`ledcWriteTone`, core 3.x), with amp enable on the queue's first note and disable when it empties.
- The note-sequencing logic (what's playing at time t) lives in `input_logic.h` as pure code, unit-tested.
- Keep `touchClick()`, now non-blocking.
- New named cues:
  - `cueStart` (two rising notes)
  - `cuePoints` (rising arpeggio C-E-G-C)
  - `cueSentToParent` (two soft notes)
  - `cueBadge` (longer fanfare)
  - `cueRedo` (low two-note)
  - `cueError`
**Fallback:** if LEDC on the DAC pin sounds wrong or is too loud, a compile-time `AUDIO_DAC_BLOCKING 1` restores the old waveform. Cues stay de-duplicated, so the freeze is still short.
**Verify on device:** volume and timbre. LEDC square wave duty is set low (e.g. duty 32/255 at 8-bit resolution) for volume.

### 1.5 The first tap after a message isn't swallowed (finding 2)
**Now:** `handleTouch` returns after clearing `msgActive` (`.ino:591`), so the next tap within 1.5 s does nothing.
**Change:**
- Clear the overlay, redraw, and pass the tap through to the screen.
- Exception: the badge celebration and the "while you were away" card (Phase 2) swallow the tap, because those are things to look at.
- Implementation: a `msgBlocking` flag set by those two.

### 1.6 Time limits fire while the screen sleeps (B9, new)
**Now:** task timeout checks run only inside `if (!display.isSleeping())` (`.ino:381`), so a time limit can't expire while the screen is dark, which is most of the time.
**Change:**
- Move the timeout loop out of that block.
- Only the redraws stay conditional on the screen being awake.

## Phase 2: Correctness of what kids see

### 2.1 "While you were away" news per child (B4, B5, redo notices, streak bonus)
**Data:** RAM-only `AwayNews news[MAX_FAMILY_MEMBERS]` in the .ino. Lost on reboot, which is accepted.
```
struct AwayNews {
    uint16_t pointsApproved;   // points from parent approvals since last seen
    uint8_t  approvedCount;
    int8_t   newBadge;         // -1 none; highest badge earned while away
    uint8_t  streakBonus;      // points from tonight's streak bonus
    uint8_t  redoCount;    char redoName[24];       // first rejected chore's name
    uint8_t  timedOutCount; char timedOutName[24];
};
```
**Filled by:**
- approve and override (points, count, badge)
- reject (redo)
- timeout (2.2)
- the daily reset streak bonus (`Scheduler::_evaluateStreaks`, via a callback/extern hook)

**Shown:**
- A child's scan with non-empty news opens `Screen::NEWS`, a full-screen card: "While you were away", one line per item, big "OK". It swallows taps (1.5) and auto-continues after 6 s.
- Then it goes to the done prompt if a chore is running, otherwise the dashboard.
- News is cleared when shown.

**B4:** approving no longer shows the badge popup on the parent's screen. The parent sees "Approved: +4 for Ava". The child sees the badge in their news.

### 2.2 Timed-out chores go back on the list and the child is told (B5)
**Now:** TIMED_OUT tasks are hidden from everyone and cleared at midnight. A 2-hour yard-work limit makes the chore silently vanish.
**Change:**
- On timeout, call `TaskEngine::putBack`. It goes back to AVAILABLE and returns to everyone if it was a first-taker chore.
- Record `timedOut` news for the child.
- The `TIMED_OUT` state stays in the enum for compatibility but is no longer entered.
- Log line `[TASK] '<name>' ran out of time`.

### 2.3 Streaks don't depend on how fast a parent approves (B7)
**Now:**
- `dailyTasksCompleted` only rises on approval (`task_engine.h:335`).
- The streak is evaluated at midnight, so a no-reminder claim still waiting at midnight counts for nothing.
- The kid sees "0/5 today, A bit behind" right after submitting.
**Change:**
- Add a helper `pendingToday(member)` counting that member's PENDING_REVIEW tasks with `!doneEarlierDay`.
- Streak qualification uses `dailyTasksCompleted + pendingToday`, with the same no-override rule. The trajectory and "x/5 today" use it too: pending shows as hollow segments (Phase 3).
- `_finalizeCompletion` does not increment `dailyTasksCompleted` when `task.doneEarlierDay` is set, because it was already counted yesterday as pending.
- Reject needs no counter change, since pending is computed live.
- **Known limit:** an override the next day on a carried-over task sets *today's* `remindedToday`. Kept as is: rare, and documented.

### 2.4 Small visual bugs (B8 + one more)
- "What kind of task?" label overlaps the first category button (`.ino` drawSelfInit, y=55 vs buttons at 55). Move the buttons to start at y=70 and update `touchSelfInit` to the same geometry. A shared constant fixes the 5 px tap offset between preset-name draw (y=275?) and touch (y=270).
- Task-screen names longer than ~22 characters wrap onto the category label. Use Font 2 for the title and shrink to text size 1 when it's longer than 24 characters, the same rule as the done prompt.
- "Min: 543s left" becomes "Min: 9m 3s left".
- Routine step length was fixed in a prior commit (39 characters). The web editor caps each line at 39 characters on save and warns ("step N shortened") instead of letting firmware truncate silently.

## Phase 3: Points and progress you can see

### 3.1 Child dashboard header (findings 1 & 4)

- **Row 3 (86–126):** a today strip:
  - the goal as N segments: filled = done, hollow = waiting for a parent, empty = to do

  - a drawn flame with streak days and "1 more = +3" (days until the next streak bonus), or "Start a streak!"

### 3.2 Cards show what they're worth

- The state icon moves left of it, or is replaced by the ✓ button (4.1).
- Card titles move to Font 2. Second-line hints stay at size 1, but in C_TXT2, not C_DIM/C_TXT3.

### 3.3 Earning feels like earning
- **Points celebration overlay:** a replacement for the "+4 pts" text message on any point award to the person at the screen (DONE, YES DONE, routine finish).
  - About 1.8 s, taps pass through after 0.5 s.
  - Big "+4" (drawn plus + Font 7 digits), "137 total" in Font 2, and the badge bar from 3.1 filling in 3 steps, animated non-blockingly from `loop()` (`celebrateStep`).
  - Sound `cuePoints`.
- **Sent for approval:** "+4 when a parent checks", `cueSentToParent`, 1.2 s.
- **New badge:** the existing NEW BADGE card, `cueBadge`. It swallows taps for 1 s (1.5).

### 3.4 "Done today" rows
- `buildDashRows` (child) appends today's COMPLETED tasks assigned to the child as a new row kind 2, after finished routines.
- They're drawn as a compact dim card: ✓, name, "+N". Tapping one does nothing.
- They give the "I did stuff today" view the reviewer asked for, without a new screen.

### 3.5 Text and contrast (finding 4)
- Kid-facing screens use Font 2 for body text and Font 4 for names and big numbers: dashboard, task screen, done prompt, routine, news, home "Scan your tag". The fonts are already compiled in (`LOAD_FONT2/4/7`), so flash stays about the same.
- Admin screens are untouched.
- Every text draw that switches fonts sets `setTextFont` explicitly and resets to GLCD at the end of the draw function, so other screens aren't affected.
- Contrast: no text in `C_DIM` on `C_BG`/`C_CARD`. Hints use `C_TXT2`.

## Phase 5: Rewards — design now, build after the owner confirms prices
Not built in this pass. It changes stored data and parent workload, and the owner said "later". The design to confirm:

  - Badges stay on lifetime points and never go backwards.
  - The dashboard star shows *spendable*; the badge screen shows lifetime.
- `/config/rewards.json`: name, cost, optional daily cap (e.g. 60 minutes of screen time a day), active flag. Edited in a new web "Rewards" tab with redemption history and manual ± adjustments (audit-logged).
- **Station:**
  - a **Shop** button on the child dashboard lists rewards (unaffordable ones greyed out, "8 more")
  - a request **holds** the points (`heldPoints`) and appears in the parent's TO CHECK list as a reward card
  - Approve spends; Redo/decline releases the hold
- **Optional "saving for" goal:** pins a reward to the header progress bar.
- **Pricing guide:** at about 5–15 points/day, 30 minutes of screen time ≈ 10 points. Retune after a week.

## Revisions after review (these override the sections above)

The plan reviewer's verdict was "approve with changes". Each required change is folded in here. Spot-checked in code: daily counters are zeroed on every boot (`storage_manager.h:78-79`); `driver/dac_cosine.h` is in the core's esp32-libs.

**R1 Audio (1.4)**
- **Commit 1a, alone:** remove every `audio.*` call from `task_engine.h` (lines 82/133/142/169/179/257/360-364). This de-duplication removes most of the freeze with no hardware risk.
- **Commit 1b, the engine:** the IDF `dac_cosine` hardware sine generator on GPIO26 (DAC ch2), driven by a one-shot `esp_timer`, so it keeps working inside the keyboard, ButtonMenu, WiFi setup and calibration modals where `loop()` doesn't run.
  - Changing notes means deleting and recreating the cosine channel, which is allowed in esp_timer task context.
  - Amp is enabled before the first note and disabled after the last (no pops).
  - Attenuation sets volume (0/6/12/18 dB).
  - Note frequencies are chosen on the generator's ~130 Hz grid: 520/650/780/1040 Hz (major triad) and a low 390 Hz for Redo/error.
- **Queue:** a new cue *replaces* the queue (it never appends), so no overflow.
- **Not mixed with `dacWrite`:** cosine and `dacWrite` are never both used at runtime.
- **Fallback:** a compile-time `AUDIO_DAC_BLOCKING 1` keeps the old blocking square wave, still de-duplicated.
- **LEDC is dropped:** it forces a 10-bit, 50% duty and can retune the backlight's timer.

**R2 Sleeping guard (1.6)**
- Move out of `!display.isSleeping()`: task timeouts, idle-lock, message expiry and detail auto-return. Only redraws stay conditional.
- This also fixes a real bug: the routine screen (3 min lock) never locked once the screen slept at 2 min.
- Redraw `DONE_PROMPT` if its task times out.

**R3 TouchGate (1.1)**
- **Time-based thresholds:** down when the press has lasted ≥25 ms (and ≥2 polls); up after ≥60 ms (and ≥3 polls) of no touch. Use the coordinates of the confirming poll.
- **`touchGate.requireRelease()`** after every modal returns: keyboard, ButtonMenu, WiFi setup, calibration, `waitTapInBox`. Also after scans and screen changes made by a modal. This way a finger lifting off the keyboard's OK can't press NEXT underneath.

**R4 Daily counts and streak (2.3), now derived live**
- **Today's done count** = COMPLETED tasks assigned to the member without `doneEarlierDay` + routines in today's `doneMask`. These persist in `active.json` / `/stats/routines.json`, so a reboot no longer wipes the day.
- **Pending (hollow) count** = PENDING_REVIEW without `doneEarlierDay`, excluding jobs the child made for themselves (`type == SELF_INIT` or `createdBy == assignedTo` for ADHOC). That closes the "I DID IT" loophole.
- **Reminded today** = any COMPLETED task (no `doneEarlierDay`) with `parentOverrodeReminder`.
- **Streak** at reset uses done + pending. The `dailyTasksCompleted` and `remindedToday` fields stay for JSON compatibility but are no longer the source of truth.
- `performDailyReset` sets `doneEarlierDay` on **every** carried-over PENDING task, not only recurring ones. `settleRejected` and `_isAlreadyActive` are fine with that.
- **Persisted last-reset date** (`/stats/day.json`): after NTP sync at boot, if the stored date isn't today, run the daily reset once. This covers being powered off over midnight, given `hasDayRolledOver` ignores its first check after boot.

**R5 Timeouts (2.2):** read the assignee before `putBack` (which returns claimed tasks to 255), then record the news for that member.

**R6 Inline ✓ (4.1)**
- Clear `noReminderToggled` before an inline `doneNowFor`.
- No inline approve for timed chores, so the parent still sees "Took Xm".
- ✓ zones ignore presses for 1 s after the list changes (any ✓, approval, page change, or background regeneration that redraws it).
- The 400 ms arrival guard is armed in `goDashboard`/`handleScan`, not in `drawDashboard`.
- The parent's approve zone is drawn differently ("OK" on amber) from a kid's "do it" ✓ (green).
- No undo, as the reviewer agreed.

**R7 Routine auto-finish (4.5):** capture the member and routine index when the 600 ms pause starts. Cancel on any `go*`, scan or screen change. `finishRoutine` takes the member explicitly instead of reading `currentUserId`.

**R8 Celebration (3.3):** any `go*` and `handleScan` cancels it, so it never paints over the next screen.

**R9 Fonts (3.5)**
- Every draw function on the converted screens *starts* with `tft.setTextFont(...)`.
- Every module entry point (parent_admin draw/touch dispatch, keyboard, wifi_setup, button_menu, milestones, setup_wizard, `drawMsgOverlay`) starts with `tft.setTextFont(1)`.
- Fit and centering use `tft.textWidth()`, not `strlen*N`.
- ASCII only (no "·" or "★"; draw the star).

**R10 Layout**
- **2.4:** use the 3x2 category grid (as in 4.6) in I Found a Job too, which removes the label overlap. One shared geometry constant for preset-name draw and touch.
- **3.2:** card lines re-spaced for a Font 2 title: title y+4 (16 px), info y+22 (size 1), hint y+33.
- **4.2 home:** fixed y values.
  - amber "to check" bar 376–412 (Font 2); in-progress line 418 (Font 2); web address 438
  - the offline box stays 318–358
  - the pixel shift (±2) still fits
- **4.2 review:** APPROVE 310–366, Approve no bonus 374–418, Redo 426–470.
- **3.1:** a name too wide for Font 4 (via `textWidth`) falls back to Font 2. Child badge-row tap zone y 48–82.
- **4.3:** "+ Job" touch zone x ≥ 226 (the code currently checks x ≥ 260 at `.ino:635/652`).
- **4.6:** button width = (290 − gaps) / count.

**R11 NEWS screen**
- Added to the `Screen` enum, `handleTouch`, `redrawCurrent` and the 60 s quickLock.
- Order on a scan: NEWS → DONE_PROMPT → dashboard.
- Shown for **any** member with news (role-neutral).
- The streak-bonus hook is a function pointer on `Scheduler` (`onStreakBonus`), set in `setup()`.
- 3.4 "Done today" becomes one summary row ("Done today: 4 jobs, +12"), drawn and touched as row kind 2 (touch does nothing). `touchDashboard` checks the kind explicitly, so it never opens a completed task.

**Optional suggestions adopted:**
- Reapply brightness when the night flag changes.
- "2 days to +3" wording.
- A ✓ on a running timed card once its minimum time has passed (finishes it).
- Quick Add (parent-only) moved to the end of Phase 4.

**Commit order:** 1a de-dup → 1b audio engine → 1 rest (TouchGate, wake, night, guard, pass-through) → 2 → 3 → 4. Each step compiles with no new warnings, passes the host tests, and is pushed.
